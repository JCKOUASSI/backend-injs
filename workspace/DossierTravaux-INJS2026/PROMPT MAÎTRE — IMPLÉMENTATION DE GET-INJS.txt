6. CONTRAINTES DE COHÉRENCE EDT

Mettre en place les contrôles pertinents pour empêcher les incohérences évidentes :

Enseignant

Éviter qu’un même enseignant soit affecté simultanément à deux séances incompatibles.

Groupe

Éviter qu’un même groupe soit programmé simultanément sur deux séances.

Salle

Éviter qu’une même salle soit occupée simultanément par deux séances.

Horaires

Vérifier :

* date ;
* heure début ;
* heure fin ;
* chevauchements ;
* durée valide.

Ressources

Contrôler les ressources nécessaires lorsque les données existantes permettent de le faire.

Ne pas construire un moteur excessivement complexe si une validation robuste et simple suffit.

9. BADGEAGE QR CODE AUTOMATIQUE

Implémenter le badgeage QR Code.

Le système doit permettre, selon l’architecture existante :

1. identifier l’utilisateur ;
2. identifier la séance ;
3. vérifier que la séance est active/pertinente ;
4. enregistrer le badgeage ;
5. déterminer la présence ;
6. empêcher les doublons ;
7. enregistrer la date/heure ;
8. conserver une trace exploitable.

Prévoir les cas :

* badge valide ;
* QR invalide ;
* QR expiré ;
* utilisateur inconnu ;
* séance inexistante ;
* badge déjà enregistré ;
* utilisateur non autorisé ;
* séance non ouverte.

⸻

10. BADGEAGE MANUEL

Le système doit également permettre un badgeage manuel par un utilisateur autorisé.

Le badgeage manuel doit être contrôlé.

Il doit permettre :

* sélectionner la séance ;
* sélectionner la personne ;
* enregistrer présence/absence/retard selon le modèle retenu ;
* enregistrer l’utilisateur ayant effectué l’opération ;
* enregistrer date/heure ;
* conserver une trace de la modification.

⸻

11. FORÇAGE DU BADGEAGE

Fonction essentielle :

Un utilisateur autorisé doit pouvoir forcer un badgeage.

Un forçage doit obligatoirement comporter un motif.

Prévoir une liste de motifs configurables ou structurés, par exemple :

* QR Code indisponible ;
* téléphone indisponible ;
* problème réseau ;
* oubli de badge ;
* correction administrative ;
* erreur de badgeage ;
* autorisation exceptionnelle ;
* autre.

Prévoir également :

* commentaire libre lorsque nécessaire ;
* utilisateur ayant forcé l’opération ;
* date/heure ;
* ancienne valeur ;
* nouvelle valeur lorsque pertinent.

Le forçage doit être auditable.
