====================================================================================================
1. CONTEXTE ET OBJECTIF GÉNÉRAL DE LA REFONTE
====================================================================================================
L'application « app-injs-lmd2026 » est le Système d'Information Universitaire de l'Institut National
de la Jeunesse et des Sports (INJS) de Marcory (Abidjan). 

Initialement centrée sur la gestion de formations continues et le badgeage de présence par QR Code
(héritage CPFAE), elle fait l'objet d'une refonte structurelle majeure pour devenir un ERP Universitaire
complet conforme aux normes LMD (CAMES et REESAO), couvrant :
  - 18 domaines fonctionnels interconnectés (Gouvernance, Scolarité, Pédagogie, GET-INJS, Présences QR,
    Notes, Jurys, Diplômation, Finances Étudiantes, Vacations, RH, Patrimoine, Stages, Statistiques).
  - 20 applications Django backend hautement testées (943 tests automatisés).
  - Une application web React 18 / Vite 7 structurée en 6 pôles universitaires.
  - Une application mobile Flutter pour le badgeage sécurisé et le contrôle anti-fraude.

6.3 CORRECTION DE L'ALERTE « CHARGEMENT DES RÉFÉRENTIELS IMPOSSIBLE » (CAMPAGNES D'ADMISSION)
====================================================================================================
- Symptôme : Bannière rouge « Chargement des référentiels impossible » sur la vue Campagnes d'admission.
- Analyse causale :
  L'endpoint `/api/scolarite/ref/formations/` et `/api/scolarite/ref/salles/` renvoyaient une erreur HTTP 404
  (« Référentiel inconnu ») car les ressources 'formations' et 'salles' n'étaient pas déclarées dans
  le dictionnaire `REFERENTIEL_FIELDS` du module `scolarite.api_views`.
- Actions correctives exécutées :
  1. `backend/scolarite/api_views.py` : Déclaration explicite des modèles `RefFormation` et `RefSalle`
     dans `REFERENTIEL_FIELDS` et `REFERENTIEL_FILTERS`.
  2. `backend/scolarite/tests/test_referentiels.py` : Ajout des tests automatisés `test_liste_formations`
     et `test_liste_salles` (32 tests exécutés avec succès).
  3. `frontend/src/pages/scolarite/Campagnes.jsx` : Résolution des libellés conviviaux de formation et
     d'année académique dans le tableau des campagnes (au lieu des simples identifiants numériques).
  4. Validation directe : Requêtes HTTP GET `/api/scolarite/ref/formations/` et `/api/scolarite/ref/salles/`
     retournent désormais le code 200 OK avec la liste complète des cycles et des salles.

6.4 CORRECTION DE L'ERREUR 405 « MÉTHODE GET NON AUTORISÉE » (RÉINSCRIPTIONS & TRANSFERTS)
====================================================================================================
- Symptôme : Encadré rouge « Données indisponibles. detail : Méthode « GET » non autorisée.
  Endpoint appelé : /scolarite/reinscriptions/ » sur l'écran Réinscriptions & transferts.
- Analyse causale :
  La vue `reinscrire` du module `scolarite/groupes_api.py` était décorée uniquement avec `@api_view(['POST'])`.
  L'écran générique de navigation `/scolarite/reinscriptions` interrogeait le backend en HTTP GET pour
  restituer le tableau des demandes de réinscription, transfert et réorientation, déclenchant l'erreur 405.
- Actions correctives exécutées :
  1. `backend/scolarite/groupes_api.py` :
     - Évolution de la vue vers `@api_view(['GET', 'POST'])`.
     - Implémentation de la consultation GET filtrant par défaut les premières inscriptions simples
       afin d'isoler le cycle de vie de scolarité (réinscriptions, transferts, réorientations, reprises, redoublements).
     - Prise en charge des filtres de recherche multi-critères (`search`, `q`, `matricule`, `nom`, `statut`, `annee`).
  2. `frontend/src/menu/ecrans.js` :
     - Définition des colonnes prioritaires (`matricule`, `etudiant`, `type_inscription_libelle`, `ref_formation`, `niveau`, `annee_academique`, `statut_libelle`, `date_inscription`).
     - Masquage des identifiants techniques étrangers (`_id`).
     - Message de liste vide pédagogique : « Aucune réinscription, transfert ou réorientation enregistré pour le moment. »
  3. `backend/scolarite/tests/test_groupes.py` :
     - Ajout du test unitaire validant le cycle complet POST réinscription suivi de la consultation GET (40 tests au vert).
  4. Validation directe :
     - Requête HTTP GET `/api/scolarite/reinscriptions/` répond HTTP 200 OK avec format de liste JSON conforme.
